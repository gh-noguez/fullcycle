# O papel do arquiteto de software.

#### O Papel do Arquiteto(a) de Software
O arquiteto(a) de software é fundamental para transformar requisitos de negócio em padrões arquiteturais, estruturando a solução como um todo.

#### Proximidade com Desenvolvedores e Orquestração
- O arquiteto está muito ligado aos componentes e ao funcionamento das coisas, por isso deve estar sempre próximo aos desenvolvedores.

- Frequentemente, o arquiteto de software também é um desenvolvedor experiente.

- Orquestra o fluxo de comunicação entre desenvolvedores e experts de domínio (pessoas que entendem a necessidade do cliente ou que utilizarão o software).

- Ajuda a garantir que o que está sendo desenvolvido esteja alinhado com as necessidades do cliente.

#### Profundo Conhecimento de Modelos Arquiteturais
- É crucial que o arquiteto(a) de software entenda profundamente os conceitos e modelos arquiteturais.

-Sem um bom leque de opções, há uma tendência de resolver problemas com base em experiências passadas limitadas (ex: sempre criar sistemas monolíticos, mesmo quando não é a melhor solução).

-Quanto maior o conhecimento em modelos arquiteturais, maior a capacidade de contextualizar o desafio e resolvê-lo da melhor forma possível.

#### Realidade do Mercado: Tech Leads e Desenvolvedores Sêniores
- Atualmente, nem sempre existe um cargo formal de "arquiteto de software". Muitos tech leads e desenvolvedores sêniores acabam assumindo decisões arquiteturais.

- Este módulo é relevante para todos que desejam entender as necessidades de negócio e ter uma gama de opções para arquitetar software, independentemente do cargo.

#### Apoio em Momentos de Crise
- O arquiteto de software frequentemente ajuda quando "o bicho está pegando" (crises, atrasos, insatisfação do cliente).

- Graças à sua experiência e "cicatrizes" de projetos passados, consegue sentar com a equipe e oferecer uma visão experiente e soluções para "corner cases" (situações não previstas).

#### Reforço de Boas Práticas de Desenvolvimento
- O arquiteto de software está diretamente ligado ao código e à implementação, não apenas a uma visão de alto nível.

- Reforça padrões de qualidade: Garante que o software tenha testes, siga princípios SOLID, tenha boas práticas de conexão com banco de dados, utilize Clean Architecture, trabalhe com eventos, etc.

- Code Review: Frequentemente, o arquiteto de software (que muitas vezes é também desenvolvedor) realiza code reviews para validar se os componentes definidos, os requisitos arquiteturais e as boas práticas estão sendo implementados corretamente.

#### Departamentos de Arquitetura
- Algumas empresas, mesmo sem o cargo de "arquiteto de software", possuem um departamento de arquitetura.

- Essa área atua como suporte aos desenvolvedores, consolidando conhecimento e auxiliando na tomada de decisões arquiteturais para novos projetos ou problemas existentes.

- A ideia não é "mandar", mas apoiar os desenvolvedores com a visão tecnológica e o contexto da empresa.
