# Pilares da arquitetura de software.

#### Pilares da Arquitetura de Software
Os pilares apresentados aqui baseiam-se na experiência em arquitetura. Sem eles, o desenvolvimento de software de qualidade se torna muito mais difícil.

1. Estrutura
- É o primeiro ponto a considerar ao arquitetar ou desenvolver qualquer software: como tudo estará estruturado.

- A estrutura deve ser de fácil evolução.

- Deve conter componentes que atendam aos objetivos do negócio.

- Sem uma estrutura clara, é difícil criar um software de qualidade que possa evoluir ao longo do tempo.

2. Componentização
- É um pilar fundamental da arquitetura de software.

- Os componentes garantem a evolução por partes do software.

- Componentes precisam se comunicar em algum momento.

- A palavra "componentização" deve estar sempre presente ao pensar em arquitetura de software. Não é possível pensar em software sem pensar em seus componentes.

3. Relacionamento entre Sistemas
- Refere-se a como os diferentes sistemas se comunicam.

- Um "sistema" pode ser parte de um software maior ou o conjunto de vários softwares.

- Os relacionamentos devem ser muito bem definidos.

- Problemas de comunicação (protocolos inapropriados, uso desnecessário de rede, regras de segurança ineficazes) podem levar a falhas.

- A forma como os sistemas se relacionam é crucial na arquitetura de software.

4. Governança
- Fundamental na arquitetura de software.

- Não se trata da burocracia corporativa, mas de ter padronização, regras, documentação e definições claras para todos.

- Inclui a escolha de linguagens, protocolos e sistemas de comunicação.

- É uma governança mais local, diferente da governança corporativa.

- Essencial para que o software possa evoluir de forma controlada.

- Define as "regras do jogo": como trabalhar com código (Git, issues, code review), princípios de desenvolvimento, etc.

- Garante que o software esteja sempre pronto para evoluir, independente da equipe.

    - Pessoas e líderes mudam; o software precisa continuar evoluindo.

    - A governança torna as pessoas "dispensáveis" no sentido de que o projeto não afunda se um membro chave sair.

    - Facilita o onboarding de novos desenvolvedores, permitindo que gerem valor mais rapidamente.

- A falta de documentação, regras e estruturas básicas pode prender um desenvolvedor a um projeto, impedindo sua progressão na carreira, pois ele se torna "indispensável" e insubstituível naquele sistema.

    - Exemplo pessoal: Onde a falta de governança impediu uma promoção, pois o conhecimento estava centralizado.

#### Em resumo, os pilares importantes para a arquitetura de software são:

- Estruturar (base sólida)

- Componentizar

- Definir regras de relacionamento entre sistemas

- Estabelecer governança (para evolução contínua)

Estes são pilares essenciais, embora não sejam os únicos, que fazem total diferença na arquitetura de software hoje.
